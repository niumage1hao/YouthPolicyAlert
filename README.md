# 🏠 青年安居与政策通 (YouthPolicyAlert)

> **为应届毕业生与青年职场人打造的城市政策与福利房源监控提醒工具。**
> 拒绝信息差，告别"手动刷政务网"——人才房/保租房配租、租房补贴、生活补贴开放时，**第一时间直达你的邮箱与微信**。

---

## 🌟 它能为你做什么

传统做法是每周手动打开十几个政务网站翻公告，容易错过申报窗口期。本项目把这件事自动化：

1. **定时抓取**各城市住建局、人社局的官方公告栏目
2. **智能筛选**出与保租房、人才公寓、应届生补贴真正相关的公告（自动排除招标、招聘、行政处罚等噪音）
3. **深入正文提取干货**——补贴多少钱、什么时候截止、什么学历能申请、年龄限制、申报入口
4. **去重后推送**到邮件 / 微信 / 飞书 / 企业微信，同一条政策绝不重复打扰

推送出来长这样（关键信息直接摆在眼前，不用点进去逐条读）：

```
[1] 示范市·全市 示范市第八批保障性租赁住房认租公告
    发布单位: 示范市住房保障局
    申报期限: 2026-09-01 至 2026-09-28      ← 从正文自动提取
    适合人群: 博士 / 硕士 / 本科 / 毕业3年内   ← 从正文自动提取
    额度/房源: 博士3000元/硕士2000元/本科1200元 ｜ 房源 860 套
    年龄要求: 35周岁以下
    原文链接: https://...
```

## ✨ 核心特性

- 🎯 **聚焦青年刚需**：保租房、人才公寓、公租房摇号、应届生租房/生活/落户补贴、青年驿站
- 🧠 **相关性打分过滤**：不是简单关键词匹配，而是加权打分 + 时效过滤，把"招聘退役大学生士兵公示"这类含关键词但无关的噪音挡在外面
- 🔎 **正文深度提取**：自动抓取详情页，提取截止日期、补贴金额、学历门槛、年龄限制、申报入口
- 🛡️ **绝不重复打扰**：URL 归一化 + 二级标题去重，同一条政策换了链接或带了时间戳参数也不会重复推送
- 📮 **推送失败自动重试**：政策入库与推送状态分离，邮件发送失败的政策会留在队列里下轮补发，**绝不静默丢失**
- 🌱 **冷启动保护**：首次运行只建立历史基线不推送，避免第一封邮件塞进几百条几年前的旧公告
- 🩺 **失效主动告警**：数据源连续抓不到内容时主动通知你，而不是让你误以为"最近没有新政策"
- ⚡️ **并发采集**：不同网站并行抓取，同一网站仍串行并保持礼貌间隔
- 🧩 **声明式规则**：加一个城市只需填 CSS 选择器，**无需写任何 Python 代码**
- 🆓 **零成本云端运行**：GitHub Actions 每日定时执行，无需自备服务器

## 🚀 快速上手

### 第一步：先做一次体检（强烈建议）

```bash
git clone https://github.com/YourUsername/YouthPolicyAlert.git
cd YouthPolicyAlert
pip install -r requirements.txt

cp config/config.example.yaml config/config.yaml
# 编辑 config/config.yaml，填入你的邮箱与授权码

python main.py doctor
```

`doctor` 会逐项告诉你：配置有没有问题、推送通道通不通、**每个数据源当前能不能抓到数据**。
它会明确区分三种状态：

- ✅ 正常抓到数据
- ⚠️ 网页能打开但一条都没解析出来（**官网改版导致选择器失效**，需更新规则）
- ❌ 网页打不开（URL 失效 / 被反爬拦截 / 网络不通）

### 第二步：验证能收到消息

```bash
python main.py test-notify
```

收到测试邮件，说明推送链路完全打通。

### 第三步：试跑与正式运行

```bash
python main.py run --dry-run    # 只抓取并打印，不写库不推送
python main.py run              # 正式执行
python main.py run --city 深圳   # 只跑某个城市
python main.py stats            # 查看统计与数据源健康状况
```

> 💡 **首次运行不会给你推送政策**，这是刻意设计的：
> 系统会先把网站上现存的公告记录为"历史基线"，只发一封「监控已启动」确认信。
> 从第二轮开始，只有**真正新发布**的政策才会推送给你。

## ☁️ GitHub Actions 零成本部署

1. **Fork 本仓库**到你的 GitHub 账号
2. 进入 `Settings` → `Secrets and variables` → `Actions` → `New repository secret`，添加：

   | Secret 名称 | 说明 | 必填 |
   |---|---|---|
   | `SMTP_USERNAME` | 发信邮箱，如 `xxx@qq.com` | ✅ |
   | `SMTP_PASSWORD` | 邮箱 **SMTP 授权码**（不是登录密码！） | ✅ |
   | `TO_EMAIL` | 接收提醒的邮箱，多个用逗号分隔 | ✅ |
   | `SMTP_HOST` | 默认 `smtp.qq.com`，用其他邮箱时填写 | ❌ |
   | `PUSHPLUS_TOKEN` | PushPlus 微信推送 Token | ❌ |
   | `SERVERCHAN_KEY` | Server酱 SendKey | ❌ |
   | `FEISHU_WEBHOOK` / `WECOM_WEBHOOK` | 群机器人地址 | ❌ |

   另可在 `Variables` 中设置 `SUBSCRIBE_CITIES`（如 `深圳,杭州`）指定订阅城市。

3. 到 `Actions` 页面手动运行一次 `Youth Policy Alert Monitor` → `Run workflow`
   （可勾选 `dry_run` 先试跑），确认日志里能抓到数据。
4. 之后每天 08:30 / 12:30 / 18:30（北京时间）自动执行。

### 关于去重数据库的持久化

工作流会把去重数据库自动提交到一个独立的 `policy-state` 分支。

> ⚠️ 早期版本使用 `actions/cache` 保存数据库，但 GitHub 官方明确声明该缓存**不保证保留**。
> 一旦缓存被清理，去重记录归零，所有历史政策会被当成"新政策"再次批量推送。
> 现已改为提交到 orphan 分支：免费、可靠、force push 覆盖不会让仓库膨胀。
> **请勿删除或合并 `policy-state` 分支。**

### 开源发布前的安全边界

- `config/config.yaml` 只用于本地配置，已经加入 `.gitignore`；公开仓库中只保留 `config/config.example.yaml`。
- 数据库、日志、验收邮件和旧版本备份不会作为开源代码的一部分提交。发布前请检查 `git status --short`，并阅读 [SECURITY.md](SECURITY.md)。
- `policy-state` 分支会随公开仓库一起公开，其中包含去重状态和运行时间等元数据，不包含通知凭据；如果不希望公开这些运行历史，请不要启用该工作流，或改用私有仓库。
- 控制台默认只监听 `127.0.0.1:8000`，没有登录认证，适合本机管理，不应直接暴露到公网。配置接口会掩码密码、Token、SendKey 和 Webhook，但这不等于提供了多用户安全边界。

## ❓ 常见问题

**Q：为什么第一次运行没收到任何政策？**
A：这是冷启动保护。首次运行只建立历史基线，避免推送几百条旧公告。你会收到一封「监控已启动」确认信。从第二轮起只推真正的新政策。

**Q：跑了几天一条政策都没收到，是坏了吗？**
A：运行 `python main.py doctor`。如果数据源显示 ⚠️ 或 ❌，说明官网改版或 URL 失效，需要更新 `config/rules.yaml`。系统也会在数据源连续失效时主动给你发告警邮件。

**Q：抓取被网站拦截（403）怎么办？**
A：程序已内置会话预热与浏览器指纹轮换。若仍被拦，多为 IP 段被封（云服务器/海外 IP 常见）。可在 `config.yaml` 里配置 `crawler.proxy`，或改在本机/国内服务器运行。

**Q：会不会重复推送同一条政策？**
A：不会。系统用归一化 URL 作主键、城市+标题作二级去重键，即使链接带时间戳参数或官网改版换了链接结构也能识别。

**Q：邮件发送失败了，那条政策是不是就丢了？**
A：不会。政策入库与推送状态是分离的，发送失败的政策会保留在待推送队列，下一轮自动补发。可在控制台「运行状态」页查看队列。

**Q：推送太多/太少怎么调？**
A：调整 `config.yaml` 中的 `crawler.relevance_threshold`（默认 2.5，调低推得更多但更杂）与 `crawler.max_age_days`（默认 45 天）。
